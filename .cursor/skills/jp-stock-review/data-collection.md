# 日股数据抓取清单与容错逻辑

> 本文件是 `SKILL.md` 的配套执行手册。本 skill 在 **Claude Code / Cursor CLI** 中运行,所有行情、汇率、利率、消息数据都需要通过 `WebFetch` / `WebSearch` 自行抓取。本文是这一抓取流程的标准操作手册 —— 避免每次都从零摸索,也避免误用数据。

---

## 何时使用本流程

**本流程是默认流程**:用户每次触发日股复盘 skill,都按本文执行。

适用条件:
- 在 Claude Code / Cursor CLI 中调用 skill(WebFetch / WebSearch 可用)
- 复盘对象是当日已收盘的日本东京证券交易所(或最近一个日股交易日)
- 数据抓取覆盖率无需 100%,**宁可缺、不可编**

## 最佳触发时间(日股口径,北京时间)

日股交易时段(东京时间;**日本不实行夏令时**,东京时间 = 北京时间 + 1 小时,全年固定):
- 早盘 9:00 - 11:30(东京) = 8:00 - 10:30(北京)
- 午休 11:30 - 12:30(东京) = 10:30 - 11:30(北京)
- 午盘 12:30 - 15:30(东京)= 11:30 - 14:30(北京)
  - 注:2024-11-05 起 TSE 收盘从 15:00 延长至 15:30(增加 closing auction 30 分钟)。在此之前 = 11:30 - 14:00(北京)

**最佳触发窗口**(均为北京时间):
- **当日 14:30 - 17:30(首选窗口)**:东京盘已 settle,日经中文网 / 雅虎日本 / Investing 中文已更新收盘数据,东证 33 业种榜亦已披露
- **当日 18:00 - 20:00**:可以跑,但贸易省外资周报(若适逢周四)可能滞后到次日;美股盘前数据尚未出来
- **当日 14:00 之前**:**禁用本流程**,东京盘尚未收盘
- **次日早上(隔夜美股已收)**:可以跑昨日日股,适合补跑;此时 ADR 隔夜数据已是"昨日日股收盘后 → 美股盘中对日股标的的预期",信号价值更完整
- **周末 / 日股节假日**:目标日回退到上一个日股交易日

## 起手判断(关键!避免最危险的"看似成功的错误")

抓数据前,**必须先回答以下三个问题**:

### Q1:目标交易日是哪一天?(日股交易日历)

**日股交易日历**(注意 **与 A 股 / 港股 / 美股完全不同步**):

日本自有节假日(2025-2026 重点参考):
- 元旦假期:1/1 ~ 1/3(三天连休)
- 成人节:1 月第 2 个周一
- 建国纪念日:2/11
- 天皇诞辰:2/23
- 春分日:3/20 或 3/21(以官方公历公布为准)
- 昭和日:4/29
- 黄金周:5/3 宪法纪念日、5/4 绿之日、5/5 儿童节(常与周末连成 4-7 日长假)
- 海洋日:7 月第 3 个周一
- 山之日:8/11
- 敬老日:9 月第 3 个周一
- 秋分日:9/22 或 9/23
- 体育日(原体育之日):10 月第 2 个周一
- 文化日:11/3
- 勤劳感恩日:11/23
- 年末休市:12/30 - 12/31

**对照 A 股**:春节、清明、五一、国庆、端午、中秋、元旦 —— A 股有但日股没的天数远多于日股有但 A 股没的天数,具体每年须 WebSearch 核对。

**判断方法**:
- 抓数据前先用 push2his 拿 `100.N225` 目标日数据,若返空说明休市,自动顺延到上一个交易日
- 不确定时 WebSearch `YYYY-MM-DD 日股 开盘 休市` 或 `YYYY-MM-DD TSE Tokyo Stock Exchange holiday`

### Q2:当前北京时间是否在最佳窗口?

参考"最佳触发时间"段,确认在 14:30 - 17:30(首选)或 18:00 - 20:00 / 次日早上(可选)。

### Q3:实时接口 vs 历史接口怎么选?

| 当前北京时间 | 接口策略 |
|---|---|
| 北京时间 14:30 ~ 20:00(同日) | **走 push2his 历史日线接口**(目标日已 settle,最稳) |
| 跨日 / 周末 / 日股节假日跑 | **必须走 push2his** |
| 目标日盘中(北京时间 8:00 - 14:30) | **禁止跑**,数据不是收盘值 |

**强烈建议:无论何时跑,默认就用 push2his**(指定 `beg=end=YYYYMMDD`),省得判断状态。与美股 skill 设计选择一致。

## Phase 0:JSON API 优先抓取(默认首选)

> 日股域东财 push2 接口覆盖范围 **比美股窄很多**:仅支持日经 225 指数、JP10Y 国债、JPY 系列汇率、日股 ADR(部分在 `106.` 主板 + 部分在 `153.` OTCBB 粉单)、日股 ETF。**TOPIX / 东证 Prime / 东证 33 业种榜 / 日经 VI / 日股个股本体行情都没有主源**,必须走 Phase 1 fallback。

### 主源:东方财富 push2 / push2his(基于 2026-05-21 实测探测)

#### 1.a 日经 225 实时(仅在北京时间 14:30 后用,推荐用 1.b)

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=100.N225&fields=f2,f3,f4,f5,f6,f12,f14
```

**字段**:`f2` 收盘价 / `f3` 涨跌幅(%) / `f4` 涨跌点 / `f5` 成交量(指数为 0,正常)/ `f6` 成交额(同前)/ `f12` 代码 / `f14` 名称

#### 1.b 日经 225 历史日线(默认推荐用此接口)

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=100.N225&klt=101&fqt=0&beg=YYYYMMDD&end=YYYYMMDD&fields1=f1,f3&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
```

返回 `data.klines` 数组(每行逗号分隔):

```
日期, 开盘, 收盘, 最高, 最低, 成交量, 成交额, 振幅%, 涨跌幅%, 涨跌额, 换手率%
```

**实测 2026-05-20 返回**:`"2026-05-20,60567.27,59804.41,60567.27,59292.25,0,0.00,2.11,-1.23,-746.18,0.00"`(N225 收 59804.41,跌 1.23%)

> ⚠️ **日经 225 在 push2 的`f5/f6`成交量/成交额恒为 0**(指数本身无成交,只有成分股有)→ 不能用此字段判断成交活跃度,**全市场成交额必须走 Phase 1**(日经中文网或东证披露的 Prime 市场总成交额)

#### 2. 日本 10Y 国债收益率(`100.` 全球指数前缀,**不是** `171.`)

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=100.JP10Y&fields=f2,f3,f4,f5,f6,f12,f14
```

**实测 2026-05-21 返回**:`f2=2.7268`(即收益率 2.7268%)/ `f3=0.21`(收益率自身的相对变化 %)

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=107.EWJ,107.DXJ,107.JPXN&fields=f2,f3,f4,f5,f6,f12,f14
```

#### 8. 通用方法:secid 反查表

任何不确定前缀的标的,先调:

```
https://searchapi.eastmoney.com/api/suggest/get?input=<关键词或代码>&type=14&token=D43BF722C8E33BDC906FB84D85E326E8
```

返回 `Data[].QuoteID` 就是 `<MktNum>.<Code>` 格式(如 `100.N225`、`119.USDJPY`、`153.SFTBY`、`106.TM`)。token 是公开常量。

**日股相关 m 值速查**:
- `100`:全球指数(N225、JP10Y 等;**注意 JP10Y 不在 `171.` 而在这里**)
- `106`:NYSE 主板日股 ADR(TM / HMC / SONY / MUFG / SMFG / MFG)
- `107`:AMEX 日股 ETF(EWJ / DXJ / JPXN)
- `119`:外汇(USDJPY / EURJPY 等)
- `153`:OTCBB 粉单日股 ADR(SFTBY / NTDOY / FRCOY / TOELY / ITOCY / MITSY / SSUMY / MARUY)

> 反查日股个股时,**用英文公司名优先**(如 "Toyota"、"SoftBank")**而非中文或 4 位日股代码** ——
> - 中文"丰田"只返回 ADR,不返回日股本体(本体本来就不在东财)
> - 4 位日股代码会被 A 股科创板 688xxx / 中证基金 / 三板代码抢匹配

### WebFetch 调 JSON API 的 prompt 模板

继承自美股 skill,WebFetch 默认会让 LLM 总结网页内容。**对 JSON 接口,必须显式禁止总结、要求保留原始数值**:

```
该 URL 返回 JSON 格式数据。处理要求:
1. 不要总结、不要转译、不要润色
2. 提取 data.diff 数组中每项的字段:f2, f3, f4, f5, f6, f12, f14
3. 按 f3 降序输出,每行格式:
   "代码=f12 | 名称=f14 | 收盘=f2 | 涨跌幅=f3% | 涨跌额=f4 | 成交量=f5 | 成交额=f6"
4. 如果 JSON 解析失败或返回空数组,直接说"接口返回空"
```

### Phase 0 数据校验

- **时间戳匹配**:push2his 返回的日期字段必须等于目标交易日;不等说明目标日非日股交易日,自动顺延
- **数值范围**:N225 单日 |涨跌幅| > 5% 视为异常需复核;JP10Y 单日 |变化| > 20 bp 罕见,需校对;USDJPY 单日 |涨跌幅| > 1.5% 是干预或重大事件信号
- **字段语义**:JP10Y 的 f2 是收益率百分数,f3 是收益率自身的相对变化(不是 bp)
- **ADR vs 当日东京盘的时序错位**:**所有 ADR 数据(`106.` / `153.`)反映前夜美股,不是当日东京盘**。报告里 ADR 表头必须明确写"前夜美股收盘";如直接说"今日丰田大涨"会误导

## Phase 1 / Phase 2:WebSearch + WebFetch 文章页

> Phase 0 仅覆盖指数总量 + 汇率 + 利率 + ADR 代理,**日股个股本体、TOPIX / 东证 33 业种榜、日经 VI、外资周报、日银动态都必须走 Phase 1**。这是日股复盘比 A 股 / 港股 / 美股都重的部分。

### Phase 1:并行 WebSearch(找到具体文章 URL)

| 目的 | 推荐 query 模板 |
|------|----------------|
| 日经 225 收盘综述 | `YYYY 年 M 月 D 日 日经225 收盘 东京股市` |
| TOPIX / 东证一部综合 | `YYYY-MM-DD TOPIX close Tokyo Stock Exchange` |
| 东证 33 业种涨跌排序 | `YYYY-MM-DD 东证33业种 涨跌幅` / `Tokyo sector performance` |
| 日经 VI(波动率) | `YYYY-MM-DD 日経VI 終値` |
| 日股个股本体(无 ADR 的标的) | `YYYY-MM-DD <公司名> 株価 終値`(如 `三菱商事 株価 終値`) |
| 半导体设备 4 雄收盘 | `YYYY-MM-DD 東京エレクトロン アドバンテスト 信越化学 ディスコ` |
| 五大商社收盘 | `YYYY-MM-DD 5大商社 株価 三菱商事 伊藤忠` |
| 外资资金流动(周报) | `YYYY-MM-DD 海外投資家 売買動向 週次` / `Japan foreign investor flow weekly` |
| 日银动态 / 经济数据 | `YYYY-MM-DD BOJ 日銀 利上げ` / `Japan CPI Tankan GDP` |

日期建议混用日文 / 中文 / 英文(`2026年5月21日` / `May 21, 2026`)。

### Phase 2:并行 WebFetch(抓每个文章的结构化数据)

权威源(按优先级):
- **日经中文网** `cn.nikkei.com`(中文,内容质量高)
- **日经新闻日文版** `www.nikkei.com`(原文最新,但部分付费墙)
- **雅虎日本财经** `finance.yahoo.co.jp/quote/<code>.T`(`<code>` 是 4 位日股代码,如 `7203.T` 丰田)—— **关键 fallback**
- **Investing 中文日股版** `cn.investing.com/equities/japan` / `cn.investing.com/indices/japan`
- **东方财富外盘频道** `quote.eastmoney.com/global/n225.html`
- **路透中文亚太** / **Bloomberg 中文亚太** / **第一财经日本频道**
- **金融时报(FT)中文网** `www.ftchinese.com`

**Prompt 模板**(以东证 33 业种为例):

```
提取页面中 YYYY-MM-DD 当日东证 33 业种(セクター)涨跌幅排名,按以下字段输出:
1. 业种名称(中文 / 日文均可)
2. 涨跌幅(%)
3. 代表标的(若文章提及)
按涨跌幅降序输出,不要总结,按列表格式。
缺项标"未获取"。
```

**Prompt 模板**(以无 ADR 个股为例):

```
提取雅虎日本财经页面上 <公司名>(代码 XXXX.T)的最新收盘价、涨跌幅、成交量、当日高低价,
以及任何当日关键新闻摘要。
保留日文原文数值,不要转换货币单位,不要总结。
```

## 已知坑(踩过的,别再踩)

1. **目标日 = 当日北京日期**(常规),但 **日股自有节假日多于 A 股**(黄金周连续 4-7 日休市最危险,5/3 - 5/5 + 周末连成 5 月初最长休市)。北京时间 5/4 在 A 股是工作日但日股全休 → 跑就会拿到 5/2 的数据,需自动顺延并明示。

2. **东财 push2 不提供日股个股本体**。`100.7203`、`116.7203`、`156.7203` 等所有候选前缀对日股 4 位代码全失败。**这是数据源硬限制**,不是探测遗漏。所有日股个股本体必须走 Phase 1。

3. **ADR 价格不等于当日东京盘**。`106.TM` / `153.TOELY` 等 ADR 反映的是**前夜美股盘中价格**,而当日东京盘已在北京时间 14:30 收盘。当天 14:30 - 21:30 这段时间抓 ADR,**拿到的是上一交易日美股收盘价**。报告中 ADR 数据必须明确标注"前夜美股收盘"。误把 ADR 当东京盘 = 最大错误模式。

4. **粉单 ADR(`153.`)是独立 secid 域**。`105.SFTBY` / `105.NTDOY` / `105.ITOCY` 全部失败。SoftBank / 任天堂 / 优衣库 / 4 大商社 / 东京电子 ADR 都在 OTCBB 粉单(`153.`)。这是关键新发现。

5. **JP10Y 在 `100.` 全球指数前缀,不在 `171.` 美债前缀**。`171.JP10Y` 失败。这是和美债 skill 不同的关键差异。

6. **USDJPY 在 `119.` 外汇前缀**。`100.USDJPY` 失败。`119.` 是东财外汇专用前缀(美元指数 DXY 走 `100.UDI` 是例外)。

7. **JPY 字段语义同美债**:`f2` 是 **收益率百分数**(JP10Y)或 **价格**(USDJPY),具体看标的类型;`f3` 是相对变化(%,不是 bp)。报告里要 bp 变动 = (今日 f2 - 昨日 f2) × 100。

8. **指数无量字段**:`100.N225` 的 `f5/f6` 成交量/成交额恒为 0。日股全市场成交额必须走 Phase 1(日经中文网 / 东证披露的 Prime 市场总成交额)。

9. **东证 33 业种榜在东财不存在**(同港股、美股 GICS):datacenter 也没有报表。**用 Phase 1 走日经中文网 / Investing 中文 / 雅虎日本** 拿涨跌幅排名。无替代主源。

10. **无 ADR 关键标的 list**(列出便于报告时明示数据来源):
    - 三菱商事 8058(MSBHY / MSBHF 在东财全失败)
    - 爱德万 6857(ATEYY / ADTTY 全失败)
    - 信越化学 4063(SHECY / SHECF 全失败)
    - 迪斯科 6146、SCREEN 7735、SUMCO 3436、迅销正股 9983(FRCOY 是其 ADR 但流动性低,建议本体走 Phase 1)
    这些标的走 **Phase 1 雅虎日本 `<code>.T`**(如 `8058.T` 三菱商事)。

11. **searchapi 不要用 4 位日股代码搜**。`8035` 会被 `688035 德邦科技`(A 股科创板)抢命中,`9984` 会被 `149984 22深能Y2`(债券)抢命中。**必须用英文公司名搜**(`Toyota`、`SoftBank`)或中文搜(部分日股有中文别名,如"索尼")。

12. **跨日陷阱(继承自 A 股 / 港股 / 美股)**:北京时间 8:00 - 14:30 是东京盘盘中,实时接口拿到的是盘中数据。**默认就用 push2his 历史接口**,无脑规避。

13. **日本不实行夏令时**。东京时间全年 = 北京时间 + 1 小时(固定时差)。这点和港股、美股都不同(美股要切夏冬令时),反而比美股 skill 简单。

14. **AI 摘要日期混淆(继承自其他 skill)**:WebSearch 拿到的 AI 摘要可能把上一交易日数据回填到当日描述。**校验:Phase 1 拿到的字段必须和 Phase 0 JSON 接口的 N225 / USDJPY 数值方向自洽**;拿不到 Phase 0 数据时,从至少 2 篇独立文章页(WebFetch 而非 AI 摘要)各取一遍,数值一致才采信。

15. **JS 动态行情页 WebFetch 必空(继承自其他 skill)**:雅虎日本动态报价页、东财外盘动态页都依赖 JS 渲染。**只能走 Phase 0 JSON API 或 Phase 1 静态文章页**。

16. **黄金周陷阱**(5 月初日股长休):5/3 - 5/5 + 周末经常连成 4-7 日休市,而 A 股 5/1 - 5/5 也休市但起止不同。这两个长假经常错开 1-2 日,跑前必须查日股是否当日开市。

17. **JP10Y `100.JP10Y` 接口在某些时段返空**(2026-05-21 实测新坑):同日早盘探测 ulist 实时返 `f2=2.7268` 正常;同日北京时间 14:30 之后再调,**ulist 实时与 push2his 历史日线都返 `rc:100` data:null**,接口不报错但无数据。原因疑似东财对日股债券域跨时段维护或推送延迟。**对策**:JP10Y 视为"P0 但易缺失"字段,Phase 0 拿不到时不要在 Phase 0 内死磕重试,**直接降级到 Phase 1**(日经中文网首页 / 雅虎日本 `^TNX-JP` / Investing 中文日本 10 年期国债页 / 路透中文亚太债券版)。

18. **ulist 批量请求粉单 ADR 偶尔丢字段**(2026-05-21 实测新坑):同一次 `ulist?secids=153.SFTBY,153.NTDOY,153.FRCOY,153.TOELY,153.ITOCY,153.MITSY,153.SSUMY,153.MARUY` 共 8 项请求,返回 `total:7` —— **FRCOY(优衣库迅销 ADR)被静默剔除**,接口不报错。其他 7 项数据正常。推测原因:粉单流动性极低的标的(FRCOY 日成交量常 < 1 万股)被东财批量接口的"无效报价过滤"误剔。**对策**:对粉单 ADR 批量请求必须 **逐项校验返回数量等于请求数量**;丢失字段单独发 ulist(`secids=153.FRCOY` 单条请求通常仍可拿)或走 Phase 1(雅虎美股 `FRCOY` 页 / 雅虎日本 `9983.T` 本体)。

19. **五大商社东京盘精确数据 Phase 1 调度**(2026-05-21 实测优化):五大商社中**仅三菱商事 8058 能从雅虎日本 `finance.yahoo.co.jp/quote/8058.T` 单页 WebFetch 拿到精确日级数据**(收盘价、涨跌幅、成交量、时间戳);WebSearch 关键词搜"五大商社 株価"基本只回决算文章和静态信息页,**无法用 WebSearch 拿到 4 商社的当日精确收盘**。**对策**:写复盘时直接 **批量 4 次并行 WebFetch 雅虎日本 `8001.T`(伊藤忠)/ `8031.T`(三井物产)/ `8053.T`(住友商事)/ `8002.T`(丸红)单页**,与 `8058.T` 合并 5 次并行请求;不要依赖 WebSearch。

## 数据冲突与校验

多源对同一字段给出不同数据时,按以下优先级采信:

1. **东财 push2his > 日经中文网 > 雅虎日本 > Investing 中文 > AI 综述**
2. **时间晚的优先**(数据 settle 后才稳定)
3. **精度高的优先**(带小数 > 模糊表述)

**强制校验项**(抓完 P0 数据后,在产出前逐条检查):

- [ ] N225 历史日线返回的日期 = 目标交易日(若不等说明目标日非交易日,自动顺延)
- [ ] N225 涨跌幅 与 EWJ ETF **前夜** 涨跌幅 方向自洽性(EWJ 反映前夜美股对日股预期,当日东京盘通常会向 EWJ 隔夜方向修正,差值过大说明信息不一致)
- [ ] USDJPY 单日变动符号 与 出口股(丰田/索尼)走势 方向自洽性(日元贬值 → 出口股涨)
- [ ] JP10Y 上行 + 银行股(MUFG/SMFG)涨幅 同向(日银加息预期 → 银行受益)
- [ ] 半导体设备 4 雄 平均涨跌幅 与 前夜美股 SMH 涨跌幅 同向
- [ ] 五大商社 平均涨跌幅 与 大宗(铜/铁矿石/原油)方向 同向
- [ ] 消息日期与复盘日期一致

任何一项失败,**标注"数据存疑,以 XXX 源为准"**,不强行消弭矛盾。

## 容错降级规则

按数据完整度分三档输出:

### 档位 A:P0 字段齐全(N225 + USDJPY + JP10Y + EWJ/DXJ + 关键 ADR 6-8 个)+ Phase 1 拿到 TOPIX + 东证 33 业种榜 + 至少 2 个无 ADR 关键标的本体

正常按 SKILL.md 10 段输出,**不降级**。

### 档位 B:P0 缺 1-2 项(例如缺 JP10Y / 缺 EWJ),或 Phase 1 拿不到东证 33 业种榜

- 报告开头顶部加一行:"本次复盘因缺失 XX 数据,完整性受限,请结合其他来源参考"
- 缺失字段涉及的段落(如缺东证 33 业种 → 第 4 节"领涨方向"只用核心观察池),**只做定性分析,不做定量判断**
- 预测部分的"依据"必须避开缺失字段
- **特例**:无 ADR 标的本体(三菱商事 / 爱德万 / 信越)本来就需要 Phase 1,Phase 0 没有不算降级

### 档位 C:P0 缺 3 项及以上(罕见,通常是网络异常或东财全域故障)

- **不输出完整复盘报告**,改为向用户说明:"公开源今日数据覆盖不足,无法完成合格复盘。可能原因:数据源限流 / 网络阻断 / 当日为日股节假日(可能 A 股是工作日但日股黄金周/年末长假)。建议稍后重试或手动贴入数据。"
- 附上已抓到的片段信息作为参考,但明确标注为"片段信息,不构成复盘"

## 禁止行为(违反即整份报告作废)

1. **禁止凭记忆补全数据**。即使你"印象中"今日日经涨了 1%,只要数据源没给出,就标"未获取"。
2. **禁止把 ADR 价格当成当日东京盘收盘**。ADR 反映**前夜美股**,不是当日东京盘。
3. **禁止把上一交易日数据当目标日数据**。push2his 在目标日为日股节假日时会返空,自动顺延并明示。
4. **禁止用"约""大约""估计"美化缺失**。
5. **禁止把盘中数据写成收盘数据**。北京时间 8:00 - 14:30 是东京盘盘中。
6. **禁止把 4 位日股代码当东财 secid**。`100.7203` / `116.7203` 全失败。日股个股要么用 ADR(注意 ADR 是前夜美股价),要么走 Phase 1。
7. **禁止编造无 ADR 标的的数据**。三菱商事 / 爱德万 / 信越 / 迪斯科 / SCREEN 必须走 Phase 1 文章页,抓不到就标"未获取"。

## 抓取效率建议

一次完整抓取预算:**Phase 0 ≤ 6 次 WebFetch + Phase 1 ≤ 6 次 WebSearch + 6 次 WebFetch**(并行执行,总耗时约 80-120 秒)。

**推荐顺序**:

1. **起手判断**(1 分钟内):确认目标日 = 当日北京日期 + 是否日股交易日(尤其黄金周 / 年末)+ 当前北京时间 ≥ 14:30
2. **Phase 0 第一波**(并行 5-6 次 WebFetch,全部走 push2his 历史接口):
   - 1.b 日经 225(`100.N225`)
   - 2 JP10Y(`100.JP10Y`)
   - 3 USDJPY + EURJPY(`119.USDJPY,119.EURJPY` 合并)
   - 4 主板 ADR(`106.TM,106.HMC,106.SONY,106.MUFG,106.SMFG,106.MFG` 合并)
   - 5 粉单 ADR(`153.SFTBY,153.NTDOY,153.FRCOY,153.TOELY,153.ITOCY,153.MITSY,153.SSUMY,153.MARUY` 合并)
   - 7 日股 ETF(`107.EWJ,107.DXJ,107.JPXN` 合并)
3. **校验 Phase 0 数据**(时间戳、N225 涨跌幅、USDJPY 方向、ADR 与 EWJ 自洽)
4. **Phase 1 第一波**(并行 4-5 次 WebSearch + WebFetch):
   - TOPIX + 日经 VI(日经中文网)
   - 东证 33 业种榜(日经中文网 / Investing 中文)
   - 无 ADR 关键标的(三菱商事 8058.T / 爱德万 6857.T / 信越 4063.T 同时拿,雅虎日本)
   - 外资周报(若适逢周四,贸易省官网或日经中文网)
5. **Phase 1 第二波**(并行 2-3 次 WebSearch):日银动态、关键经济数据、当日重大消息
6. 终止抓取,进入写作

超过这个量级说明数据源失效,应该换策略而非盲目加次数。
