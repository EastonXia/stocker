# 东亚科技链(台股+韩股)数据抓取清单与容错逻辑

> 本文件是 `SKILL.md` 的配套执行手册。本 skill 在 **Claude Code / Cursor CLI** 中运行,所有行情、汇率、消息数据都需要通过 `WebFetch` / `WebSearch` 自行抓取。本文是这一抓取流程的标准操作手册。

---

## 何时使用本流程

**本流程是默认流程**:用户每次触发东亚科技链复盘 skill,都按本文执行。

适用条件:
- 在 Claude Code / Cursor CLI 中调用 skill(WebFetch / WebSearch 可用)
- 复盘对象是当日已收盘的台股 + 韩股(或最近一个双市场交易日)
- 数据抓取覆盖率无需 100%,**宁可缺、不可编**

## 最佳触发时间(双市场口径,北京时间)

**台股交易时段**(台北时间;台湾不实行夏令时,**台北时间 = 北京时间** 完全一致):
- 盘前:8:30 - 9:00
- 正常时段:9:00 - 13:30(北京时间)
- 收盘竞价:13:25 - 13:30(随机时段)
- 北京时间收盘 = **13:30**(全年固定)

**韩股交易时段**(首尔时间;韩国不实行夏令时,首尔时间 = 北京时间 + 1 小时):
- 盘前:7:30 - 8:30(北京)
- 正常时段:9:00 - 15:30(首尔) = **8:00 - 14:30(北京)**
- 收盘竞价:14:20 - 14:30(北京)
- 北京时间收盘 = **14:30**(全年固定)

**最佳触发窗口**(均为北京时间):
- **14:30 - 17:00(首选)**:两市都已 settle,经济日报 / 雅虎台湾 / Naver Finance / Investing 中文已更新收盘数据;与 jp-stock 复盘同窗口可串联
- **当日 13:30 - 14:30**:仅台股已收,韩股仍在尾盘,**禁用本流程**(韩股数据未 settle)
- **当日 13:30 之前**:**禁用本流程**,两市都在盘中

## 起手判断(关键)

抓数据前,**必须先回答以下三个问题**:

### Q1:目标交易日是哪一天?+ 当日台 / 韩双市场是否都开市?

**目标日** = 当前北京日期(常规情况;若跨日 / 周末跑,回退到上一个双市场都开市的交易日)

**台股交易日历**(注意 **与 A 股 / 韩股都不完全同步**):
- 春节(农历):休 5-9 天(2025 春节 1/27-1/31 / 2026 春节 2/16-2/22 等,与 A 股部分重叠但起止有差)
- 和平纪念日 2/28
- 儿童节 + 清明 连休 4/4-4/6(若周末邻接会扩成 4 天)
- 端午(农历五月初五)+ 中秋(农历八月十五):休 1-3 天
- 国庆 10/10 + 双十节:**台股特有,A 股不休**
- 元旦 1/1 / 跨年 12/31:仅 1 天

**韩股交易日历**(注意 **春节天数与 A 股 / 台股不同步**):
- 元旦 1/1
- 春节(农历):休 3 天(与 A 股 8 天 / 台股 5-9 天不同)
- 独立运动纪念日 3/1
- 儿童节 5/5
- 释迦诞辰日(农历四月初八)
- 显忠日 6/6
- 光复节 8/15(**韩国特有,A 股 / 台股都不休**)
- 中秋节(农历八月十五前后 3 天):休 3 天
- 开天节 10/3 + 韩文节 10/9(**韩国特有**)
- 圣诞节 12/25

**典型错位**:
- 春节:三地都休但天数不同(韩股最短 3 天,台股 5-9 天,A 股 8 天)
- 5/5 儿童节:韩股休,台股可能休(看是否与清明邻接),A 股不休
- 国庆 10/10:仅台股休
- 8/15 光复节:仅韩股休
- 10/3 开天节 + 10/9 韩文节:仅韩股休
- A 股 10/1-10/7 国庆长假:仅 A 股休,台股 / 韩股正常(10/10 台股自己再休)

**判断方法**:
- 抓数据前先 ulist 拿 `100.KS11` 目标日数据,若返空说明韩股休市
- 不确定时 WebSearch `YYYY-MM-DD Taiwan stock market open` / `YYYY-MM-DD KOSPI holiday`

**休市处理**:
- 仅一方休市:跑开市的一方,报告标题改为"X 股专题",归档文件名加后缀 `-仅韩股` / `-仅台股`
- 双方都休:直接告知用户休市,跳过

### Q2:当前北京时间是否在最佳窗口?

参考"最佳触发时间"段,确认在 14:30 - 17:00 之间。13:30 - 14:30 因韩股未收禁用。

### Q3:实时接口 vs 历史接口怎么选?

| 当前北京时间 | 接口策略 |
|---|---|
| 北京时间 14:30 ~ 20:00(同日) | **走 push2his 历史日线接口**(目标日已 settle,最稳) |
| 跨日 / 周末 / 台股或韩股节假日跑 | **必须走 push2his** |
| 目标日盘中(北京时间 8:00 - 14:30) | **禁止跑**,数据不是收盘值 |

**强烈建议:无论何时跑,默认就用 push2his**(指定 `beg=end=YYYYMMDD`),与 jp-stock skill 设计选择一致。

10. **春节交易日历错位**:A 股 / 台股 / 韩股 春节休市天数都不同(A 股 8 天 / 台股 5-9 天 / 韩股 3 天),起止日期常错开 1-3 日。跑前必须查双方是否同时开市。

12. **光复节 8/15 仅韩股休 / 开天节 10/3 仅韩股休 / 韩文节 10/9 仅韩股休**:这三个日期容易漏判,跑前必须核对。

13. **5/5 儿童节双方都可能休**:台湾儿童节 + 清明 连休 4/4-4/6;韩国儿童节 5/5。两者错开但同期都可能休 → 跑前分别校验。

14. **跨日陷阱**(承自其他 skill):北京时间 8:00 - 14:30 是双市场盘中,实时接口拿到的是盘中数据。**默认走 push2his 历史接口**无脑规避。

15. **AI 摘要日期混淆**(承自其他 skill):WebSearch 拿到的 AI 摘要可能把上一交易日数据回填到当日描述。Phase 1 拿到的字段必须和 Phase 0 数值方向自洽。

16. **JS 动态行情页 WebFetch 必空**(承自其他 skill):雅虎台湾动态报价页、Naver Finance 动态页都依赖 JS 渲染。**只走静态文章页或快照页**。

17. **东财 push2 接口偶尔限流空响应**(2026-05-21 / 5-22 两轮实测,严重升级):本 skill 首次探测 + 首次实战连续两天遇到 push2 / push2his 返 HTTP=000 / `Empty reply from server`,SSL 握手正常但 HTTP 无响应,**横跨 5/21 17:34 - 5/22 16:30 多次重试均失败,持续 ≥ 20 小时**。其他 skill(jp-stock 同期可用)未遇到 → 推测 **east-asia-tech 用到的 secid 集合(`100.KS11` / `119.USDKRW` / `153.SSNGY` 等)可能命中东财对低频 / 海外标的的限流策略,A 股 / 港股 / 美股核心 secid 不受影响**。**对策**:本 skill **默认假设 Phase 0 不可用** → 起手直接走 Phase 1 全套 fallback,Phase 0 当作"如果碰巧能用就拿一下"的奖励,不作为前置依赖;并行 ≤ 2 次 Bash 调 push2,任一失败立即跳转 Phase 1。

18. **WebFetch 雅虎台湾 / Naver Finance 单页只显示最新一日**(2026-05-22 实战新坑):跑 5/21 复盘时 WebFetch 雅虎台湾 `2330.TW`,返回的是 5/22 数据(最新一日);只能从 5/22 数据"前收"字段倒推 5/21 收盘值。**对策**:WebFetch 单页 prompt 必须加一句 **"如果页面只显示一日数据,请明确返回这是哪一天,以及前一日(N-1 日)的收盘价用于交叉验证"**;另一对策是改抓 `tw.stock.yahoo.com/quote/2330.TW/history` 历史数据子页。

19. **多源 KOSPI / TAIEX 收盘数值差异**(2026-05-22 实战新坑):同一日 KOSPI 5/21 收盘 Seoul Economic 报 **7,815.59**,Business Standard 报 **7,787.74**,差 28 点(~0.36%);TAIEX 多源也有 +3.9% vs +3.8% 之差。原因:**closing auction vs primary close、不同时点抓取的盘后修正、汇率换算差**。**对策**:多源差值 < 0.5% 时按 **官方源(韩交所 / 台证交)优先**,无官方源时取多源数值的中位数;并在报告中标注"多源差异 0.X%,以 XXX 源为准"。

20. **合并版次要标的(联发科 / 鸿海 / Naver / 现代)单日精确数据 Phase 1 难以同时拿全**(2026-05-22 实战观察):时间预算限制下,Phase 1 抓 6-8 次 WebFetch 后,4 雄(台积电 + 联发科 / 三星 + SK 海力士)已耗尽预算 → 次要标的只能"由 KOSPI / TAIEX 涨幅 + 综合新闻定性",拿不到单日 +X% 精确数值。**对策(接受性约束)**:合并版 skill **明确放弃 4 雄之外标的的精确数值**,改用 "推测 +X% ~ +Y% 区间" + "随大盘走势"定性表述;若 4 雄精确数据已齐全且时间允许,再 best-effort 抓 1-2 个次要标的。这是合并版相对单市场 skill 的设计取舍。

## 数据冲突与校验

多源对同一字段给出不同数据时,按以下优先级采信:

1. **东财 push2his > 雅虎台湾 / Naver Finance(本体官方源)> Investing 中文 / 经济日报 > AI 综述**
2. **时间晚的优先**(数据 settle 后才稳定)
3. **精度高的优先**(带小数 > 模糊表述)

**强制校验项**(抓完 P0 数据后,在产出前逐条检查):

- [ ] KOSPI 历史日线返回的日期 = 目标交易日(若不等说明韩股休市,自动顺延或转专题)
- [ ] TAIEX(Phase 1)与台积电 2330 本体(Phase 1)涨跌方向自洽性(台积电占 TAIEX 权重 ~30%,极强相关)
- [ ] KOSPI 与三星 005930 + SK 海力士 000660 涨跌方向自洽性(两者占 KOSPI 权重 ~25-30%)
- [ ] 台积电 ADR(前夜美股)与台积电本体(当日台北盘)的差值(差值大说明前夜美股有显著反向行情)
- [ ] USDKRW 单日变动符号 与 出口股(三星 / 现代)走势 方向自洽(韩元贬值 → 出口股涨)
- [ ] USDTWD 单日变动符号 与 台积电 + 鸿海 走势 方向自洽
- [ ] 半导体四雄(台积电 + 联发科 + 三星 + SK 海力士)平均与 美股 SMH 前夜 方向自洽
- [ ] 消息日期与复盘日期一致

任何一项失败,**标注"数据存疑,以 XXX 源为准"**,不强行消弭矛盾。

## 容错降级规则

按数据完整度分三档输出:

### 档位 A:P0 字段齐全(KOSPI + TAIEX + 台积电/三星/SK 海力士本体 + USDKRW + USDTWD)+ Phase 1 拿到至少 6 只核心个股本体 + 双市场板块榜/关键消息

正常按 SKILL.md 10 段输出,**不降级**。

### 档位 B:P0 缺 1-2 项(例如缺 USDTWD / 缺 KOSDAQ / 缺一只核心标的本体)

- 报告开头顶部加一行:"本次复盘因缺失 XX 数据,完整性受限,请结合其他来源参考"
- 缺失字段涉及的段落只做定性分析,不做定量判断
- 预测部分的"依据"必须避开缺失字段
- **特例**:Phase 0 主源仅 KOSPI + USDKRW + 三星 GDR + 台积电 ADR 四项,**其余字段本来就需要 Phase 1,Phase 0 没有不算降级**

### 档位 C:Phase 1 也大面积失败(罕见,通常是当日是双市场都休或网络异常)

- **不输出完整复盘报告**,改为向用户说明:"公开源今日数据覆盖不足,无法完成合格复盘。可能原因:数据源限流 / 网络阻断 / 当日为台 / 韩双市场都休假日。建议稍后重试或手动贴入数据。"
- 附上已抓到的片段信息,但明确标注"片段信息,不构成复盘"

## 禁止行为(违反即整份报告作废)

1. **禁止凭记忆补全数据**。
2. **禁止把 ADR / GDR 价格当成当日台北 / 首尔盘收盘**。
3. **禁止把上一交易日数据当目标日数据**。
4. **禁止用"约""大约""估计"美化缺失**。
5. **禁止把盘中数据写成收盘数据**。北京时间 8:00 - 14:30 是双市场盘中。
6. **禁止把 4 / 6 位代码当东财 secid**。台股 / 韩股个股本体走 Phase 1。
7. **禁止把粉单 GDR(`153.SSNGY` 三星)价格当成首尔盘**。粉单流动性极低,只作方向参考。
8. **禁止编造无主源的板块榜**。TAIEX 类股榜 / KOSPI 业种榜必须从 Phase 1 真实文章页抓取。

## 抓取效率建议

一次完整抓取预算:**Phase 0 ≤ 4 次 WebFetch + Phase 1 ≤ 8 次 WebSearch + 12 次 WebFetch**(并行执行,总耗时约 90-150 秒,**比单市场 skill 略多**因双市场负载)。

**推荐顺序**:

1. **起手判断**(1 分钟内):确认目标日 + 双市场开市状态 + 当前北京时间 ≥ 14:30
2. **Phase 0 第一波**(并行 3-4 次 WebFetch):
   - KOSPI 历史日线(`100.KS11`)
   - USDKRW 历史日线(`119.USDKRW`)
   - 三星电子 GDR + 台积电 ADR 实时(`153.SSNGY,106.TSM`)
   - EWT + EWY ETF 实时(`107.EWT,107.EWY`,**待首次实战确认**)
3. **校验 Phase 0 数据**
4. **Phase 1 第一波**(并行 6-8 次 WebFetch,**这是核心数据抓取**):
   - 雅虎台湾 `^TWII` / `2330.TW` / `2454.TW` / `2317.TW` / `2303.TW` / `2382.TW`(TAIEX + 5 只台股核心)
   - Naver Finance `005930` / `000660` / `035420` / `005380` / `066570` / `035720`(三星 + SK 海力士 + Naver + 现代 + LG + Kakao)
   - USDTWD(Investing 中文 / 央行)
   - 双市场板块榜(经济日报 / Naver)
5. **Phase 2 第二波**(并行 2-3 次 WebSearch):央行 / 经济数据 / 关键消息
6. 终止抓取,进入写作

超过这个量级说明数据源失效,应该换策略而非盲目加次数。
