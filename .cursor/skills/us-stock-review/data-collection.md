# 美股数据抓取清单与容错逻辑

> 本文件是 `SKILL.md` 的配套执行手册。本 skill 在 **Claude Code / Cursor CLI** 中运行,所有行情、利率、汇率、消息数据都需要通过 `WebFetch` / `WebSearch` 自行抓取。本文是这一抓取流程的标准操作手册 —— 避免每次都从零摸索,也避免误用数据。

---

## 何时使用本流程

**本流程是默认流程**:用户每次触发美股复盘 skill,都按本文执行。

适用条件:
- 在 Claude Code / Cursor CLI 中调用 skill(WebFetch / WebSearch 可用)
- 复盘对象是昨夜已收盘的美股市场(或最近一个美股交易日)
- 数据抓取覆盖率无需 100%,**宁可缺、不可编**

## 最佳触发时间(美股口径,北京时间)

美股交易时段(北京时间):
- **夏令时**(每年 3 月第 2 个周日 ~ 11 月第 1 个周日):
  - 盘前 16:00-21:30
  - 正常时段 21:30 - 次日 4:00
  - 盘后 次日 4:00-8:00
- **冬令时**(11 月 ~ 次年 3 月):整体后移 1 小时
  - 盘前 17:00-22:30
  - 正常时段 22:30 - 次日 5:00
  - 盘后 次日 5:00-9:00

**最佳触发窗口**(均为北京时间):
- **次日 7:00 - 9:00(夏令时)/ 8:00 - 10:00(冬令时)**:盘后异动告一段落,东财数据已完整稳定,**首选窗口**
- **次日上午 10:00 之前**:港股开盘前最后机会,适合补跑;此后港股已开盘,中概联动判断意义降低
- **次日中午之后(>12:00)**:数据完整度依然高,但 ADR 联动隐含已被港股 / A 股开盘消化,信息价值下降
- **当日北京时间 21:30 - 次日 4:00 / 5:00**:**禁用本流程**,此时美股盘中,实时接口拿到的不是收盘数据
- **当日北京时间 4:00 / 5:00 - 7:00**:可以跑,但部分盘后数据(尤其是财报后异动)还在变化,**不推荐**

---

## 起手判断(关键!避免最危险的"看似成功的错误")

抓数据前,**必须先回答以下三个问题**:

### Q1:目标交易日是哪一天?(美股交易日历 + 时区映射)

**核心难点**:北京时间次日早上跑时,目标日是 **昨夜的美股交易日**,**不是当前北京日期**。

| 当前北京时间 | 目标美股交易日 |
|---|---|
| 周二 ~ 周六的早上(7:00-12:00) | 上一个美股交易日(等于"今天-1 日"或"周一-1 日")|
| 周一早上 | 美股周五(因为周末美股不开市) |
| 周日早上 | 美股周五 |
| 美国节假日次日早上 | 美股的上一个交易日(可能跨好几天) |

**美股交易日历**(注意 **与 A 股 / 港股 / 中国节假日完全不同步**):
- 美股自有节假日:**马丁路德金日(1 月第 3 个周一)、总统日(2 月第 3 个周一)、耶稣受难日(春分后第一个满月后的周五)、阵亡将士纪念日(5 月最后一个周一)、独立日(7/4)、劳动节(9 月第一个周一)、感恩节(11 月第 4 个周四)、感恩节后周五半日、圣诞节(12/25)** 等休市
- 一些日子是"半日市"(如感恩节后周五、圣诞前夜),收盘提前 3 小时

**判断方法**:
- 抓数据前先 push2his 拿目标日数据,若返空说明休市,自动顺延到上一个交易日
- 不确定时 WebSearch `YYYY-MM-DD US stock market open or closed`

### Q2:当前是夏令时还是冬令时?

- 夏令时(3 月第 2 个周日 ~ 11 月第 1 个周日):美股收盘 = 北京时间次日 4:00
- 冬令时(其余时间):美股收盘 = 北京时间次日 5:00

**为什么重要**:决定北京时间凌晨 4:00-5:00 这 1 小时是否落在美股盘中(可能拿到非收盘数据)。但若用 push2his 历史接口,**完全规避此问题**。

### Q3:实时接口 vs 历史接口怎么选?

| 当前北京时间 | 接口策略 |
|---|---|
| 北京时间次日早上 7:00 后 | **默认走 push2his 历史日线接口**(目标日已 settle,最稳) |
| 跨日 / 周末 / 美股节假日跑 | **必须走 push2his** |
| 目标日盘中(北京时间 21:30 - 次日 4:00 / 5:00) | **禁止跑**,数据不是收盘值 |

**强烈建议:无论何时跑,默认就用 push2his**(指定 `beg=end=YYYYMMDD`),省得判断状态。这是和 A 股 / 港股 skill 不同的设计选择,因为美股复盘几乎都在收盘之后跑,实时接口的优势没有,反而带来跨日风险。

### WebFetch 调 JSON API 的 prompt 模板

WebFetch 默认会让 LLM 总结网页内容。**对 JSON 接口,必须显式禁止总结、要求保留原始数值**:

```
该 URL 返回 JSON 格式数据。处理要求:
1. 不要总结、不要转译、不要润色
2. 提取 data.diff 数组中每项的字段:f2, f3, f4, f5, f6, f12, f14
3. 按 f3 降序输出,每行格式:
   "代码=f12 | 名称=f14 | 收盘=f2 | 涨跌幅=f3% | 涨跌额=f4 | 成交量=f5 | 成交额=f6"
4. 如果 JSON 解析失败或返回空数组,直接说"接口返回空"
```

调 push2his 时模板类似:

```
该 URL 返回 JSON。提取 data.klines 数组的每行(逗号分隔字符串),按以下结构输出原文:
"日期, 开, 收, 高, 低, 成交量, 成交额, 振幅%, 涨跌幅%, 涨跌额, 换手率%"
不要总结。如果 klines 为空数组,说"目标日返空(可能是非交易日)"。
```

### Phase 0 数据校验

- **时间戳匹配**:push2his 返回的日期字段必须等于目标交易日;不等说明目标日非交易日,自动顺延
- **数值范围**:三大指数单日涨跌幅 |x| > 5% 视为异常需复核;美债 10Y 单日 |变化| > 30 bp 罕见,需校对
- **字段语义**:美债 `171.<代码>` 的 f2 是收益率百分数(不是价格),`f3` 是收益率自身的相对变化(不是 bp)
- **多接口交叉**:1.b 拿到的 SPX 涨跌幅与 4 拿到的 11 个 SPDR ETF 涨跌幅加权应大致自洽;偏差 > 0.5% 需复核

### Phase 0 失败时的处理

- **单接口失败**(返回空 / 4xx / 5xx):等 3-5 秒重试 1 次,仍失败切备源
- **腾讯备源**:`https://qt.gtimg.cn/q=usAAPL.OQ`(返回 ~ 字段分隔)
- **新浪备源**:`https://hq.sinajs.cn/list=gb_aapl`(代码全小写)
- **全部主源 + 备源失败**:走 Phase 1 WebSearch 路径,但报告必须标明"Phase 0 全失败,数据来自二手综述,精度下降"

## 已知坑(踩过的,别再踩)

1. **目标日 = 昨夜美股交易日,不是当前北京日期**(最容易踩)。北京时间 5/9 周六早上跑,目标日是美股 5/8 周五;周一早上跑,目标日是美股 5/8 周五(因为周末美股不开市)。文件名日期、push2his 的 `beg=end=` 参数都用美股交易日。

2. **`100.NDX` 命名陷阱**:东财把 `100.NDX` 标注为"纳斯达克"但实际数值是 **综合指数**(IXIC)。**纳指 100 必须用 `100.NDX100`**。报告中明确两者口径分开。

3. **罗素 2000 / 费半没有指数 secid**:只能用 ETF `107.IWM` / `105.SMH` 替代。这是数据源硬限制,不是探测遗漏。报告中可写"以 IWM ETF 替代罗素 2000 收盘"或直接报 ETF 价位。

4. **GICS 行业板块榜在美股域不存在**(同港股):datacenter `RPT_USSTOCK_INDUSTRY` 等全返"报表配置不存在",push2 域 `m:105/106/107+t:X` 全部 `data:null`。**用 SPDR 11 大行业 ETF(XL 系列)代偿是最干净的方案**,11 只全通且流动性好,涨跌幅 = 行业当日表现。

5. **中概股前缀不能想当然**:BABA 在 NYSE → `106.BABA`(不是 105),KWEB 在 AMEX → `107.KWEB`(不是 105 也不是 106)。其他多数中概在 NASDAQ → `105.<代码>`。**首次添加新中概标的时,用 searchapi 反查**。

6. **SPDR ETF 全在 AMEX**:必须用 `107.` 前缀,`105.XLK` / `106.XLK` 全部失败。

7. **美元指数东财别名 UDI**:`100.DXY` / `100.USDX` 全部失败。东财内部叫 UDI(United Dollar Index)。

8. **美债走 `171.` 独立前缀**:`100.US10Y` / `100.TNX` / `100.UST10Y` 全部失败。`171.US10Y` / `171.US30Y` 通,但 `171.US02Y` / `171.US05Y` 失败。如需 2 年期或 5 年期,走 Phase 1 fallback。

9. **美债字段语义偏差**:`171.<代码>` 的 `f2` 是 **收益率百分数**(不是价格),`f3` 是 **收益率自身的相对变化**(%,不是 bp)。报告里要 bp 变动 = 今日 f2 - 昨日 f2 然后 × 100。

10. **VIX 现货无 secid**:`100.VIX` / `1.VIX` / `100.VXX` 全失败。用 `107.VIXY` ETF 当方向参考,**但 VIXY 是杠杆产品,涨跌幅不能等同于 VIX 数值**。要 VIX 数值必须 Phase 1(雅虎 `^VIX`)。

11. **盘前盘后无主源**:`ulist.np` 不支持 `extend=1`/`pre=1`,`stock/get` 字段 `f250-f297` 全 0 或常量。**必须 Phase 1**(腾讯 `usAAPL.OQ`、新浪 `gb_aapl`、东财个股页 `quote.eastmoney.com/us/<TICKER>.html`)。

12. **财报日历无主源**:datacenter 所有 `RPT_USSTOCK_*` / `RPT_US*` 财报报表全部"报表配置不存在",东财美股 F10 页"无 F10 资料"。**必须 Phase 1**(雅虎 `finance.yahoo.com/calendar/earnings?day=YYYY-MM-DD`、Investing 中文、moomoo)。

13. **跨日陷阱(继承自 A 股 / 港股)**:北京时间 21:30 - 次日 4:00(夏)/ 5:00(冬)是美股盘中,实时接口拿到的是盘中数据。**默认就用 push2his 历史接口**,无脑规避。

14. **夏冬令时切换**:每年 3 月第 2 个周日开始夏令时,11 月第 1 个周日结束。这影响"目标日 vs 当前日"的临界判断,但走 push2his 不受影响。

15. **AI 摘要日期混淆(继承自 A 股 / 港股)**:WebSearch 拿到的 AI 摘要会把上一交易日数据回填到当日描述。校验:Phase 1 拿到的字段必须和 Phase 0 JSON 接口交叉对比;拿不到 Phase 0 数据时,从至少 2 篇独立文章页(WebFetch 而非 AI 摘要)各取一遍,数值一致才采信。

16. **JS 动态行情页 WebFetch 必空(继承自 A 股 / 港股)**:东财美股个股动态页、雪球动态页都依赖 JS 渲染。这类页面只能走 Phase 0 JSON API 或 Phase 1 静态文章页。

## 数据冲突与校验

多源对同一字段给出不同数据时,按以下优先级采信:

1. **东财 push2his > 备源(腾讯/新浪)> 文章综述**
2. **时间晚的优先**(数据 settle 后才稳定)
3. **精度高的优先**(带小数 > 模糊表述)

**强制校验项**(抓完 P0 数据后,在产出前逐条检查):

- [ ] 三大指数的涨跌幅与点位算术自洽(涨跌点位 ≈ 昨收 × 涨跌幅)
- [ ] 标普涨跌幅与 SPDR 11 ETF 加权涨跌幅大致自洽(偏差 < 0.5%)
- [ ] 七巨头平均涨跌幅与纳指 100 涨跌幅偏差 < 1.5%(偏差大 = 极端集中度)
- [ ] 中概股 KWEB ETF 涨跌幅与 BABA/JD/PDD/NTES 等头部成分股加权大致自洽
- [ ] 美债 10Y 收益率与 DJIA / SPX 走势自洽性(收益率上行 + 科技股下跌 是常见组合)
- [ ] VIX 方向与三大指数方向反向(指数大跌 → VIX 通常上行;若同向需高度警惕数据错)
- [ ] 消息日期与复盘日期一致

任何一项失败,**标注"数据存疑,以 XXX 源为准"**,不强行消弭矛盾。

## 容错降级规则

按数据完整度分三档输出:

### 档位 A:P0 字段齐全(三大指数 + 纳 100 + 罗素 + 费半 + DXY + 10Y 美债 + VIX + M7 + SPDR 11 ETF)

正常按 SKILL.md 10 段输出,数据缺失项逐条标注"未获取",**不降级**。

### 档位 B:P0 缺 1-2 项(例如缺 VIX 现货 / 缺财报日历)

- 报告开头顶部加一行:"本次复盘因缺失 XX 数据,完整性受限,请结合其他来源参考"
- 缺失字段涉及的段落(如缺 VIX → 第 7 节中 VIX 部分用 VIXY ETF 替代并标注),**只做定性分析,不做定量判断**
- 预测部分的"依据"必须避开缺失字段
- **特例**:VIX 现货、盘前盘后、财报日历这三类本来就需要 Phase 1,Phase 0 没有不算降级,只要 Phase 1 拿到就算正常

### 档位 C:P0 缺 3 项及以上(罕见,通常是网络异常或东财全域故障)

- **不输出完整复盘报告**,改为向用户说明:"公开源今日数据覆盖不足,无法完成合格复盘。可能原因:数据源限流 / 网络阻断 / 当日为美股节假日。建议稍后重试或手动贴入数据。"
- 附上已抓到的片段信息作为参考,但明确标注为"片段信息,不构成复盘"

## 禁止行为(违反即整份报告作废)

1. **禁止凭记忆补全数据**。即使你"印象中"昨夜纳指涨了 1%,只要数据源没给出,就标"未获取"。
2. **禁止把当前北京日期当成美股交易日**。目标日 = 昨夜美股交易日(不是今天)。
3. **禁止把上一交易日数据当目标日数据**。push2his 在目标日为美股节假日时会返空,自动顺延。
4. **禁止用"约""大约""估计"美化缺失**。
5. **禁止把盘中数据写成收盘数据**。北京时间 21:30 - 次日 4:00/5:00 是美股盘中,实时接口拿到的不是收盘。
6. **禁止把 VIXY ETF 涨跌幅当 VIX 现货数值**。VIXY 是杠杆产品,日内涨跌幅与 VIX 现货差距大。
7. **禁止编造未来财报日历**。次日盘前 / 盘后财报必须从 Phase 1 真实 earnings calendar 文章页抓取。

## 抓取效率建议

一次完整抓取预算:**Phase 0 ≤ 8 次 WebFetch + Phase 2 ≤ 4 次 WebSearch + 4 次 WebFetch**(并行执行,总耗时约 60-100 秒)。

**推荐顺序**:

1. **起手判断**(1 分钟内):确认目标交易日(昨夜美股) + 夏冬令时 + 当前北京时间
2. **Phase 0 第一波**(并行 5-6 次 WebFetch,全部走 push2his 历史接口):
   - 1.b 五大指数 + 罗素 ETF + 费半 ETF(并行 6 个 secid 一次合并请求 ulist 也可,但 push2his 必须单独发)
   - 2 Magnificent 7
   - 3 中概股关键标的(BABA/JD/PDD/NTES/BILI/KWEB/TME/BIDU)
   - 4 SPDR 11 大行业 ETF
   - 5 美元指数 UDI
   - 6 美债 10Y / 30Y
3. **Phase 0 第二波**:VIXY ETF 历史(1 次)
4. **校验 Phase 0 数据**(数值合理性、时间戳、跨接口自洽)
5. **Phase 1 / 2 抓三类无主源数据**(并行):
   - VIX 现货收盘(雅虎 `^VIX` 或 Investing)
   - 当日盘前盘后异动 TOP(雪球美股盘后异动 / 东财个股页)
   - 当日重磅财报复盘 + 明日财报日历(雅虎 / Investing / moomoo)
6. **Phase 2 抓消息面**(并行 2-3 次 WebSearch):联储 / 经济数据 / 重大事件
7. 终止抓取,进入写作

超过这个量级说明数据源失效,应该换策略而非盲目加次数。
