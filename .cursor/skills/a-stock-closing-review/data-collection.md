# 数据抓取清单与容错逻辑

> 本文件是 `SKILL.md` 的配套执行手册。本 skill 在 **Claude Code / Cursor CLI** 中运行,所有行情、资金、消息数据都需要通过 `WebFetch` / `WebSearch` 自行抓取,本文是这一抓取流程的标准操作手册 —— 避免每次都从零摸索,也避免误用数据。

---

## 何时使用本流程

**本流程是默认流程**:用户每次触发 A 股收盘复盘 skill,都按本文执行。

适用条件:
- 在 Claude Code / Cursor CLI 中调用 skill(WebFetch / WebSearch 可用)
- 复盘对象是当日已收盘的 A 股市场(或最近一个交易日)
- 数据抓取覆盖率无需 100%,**宁可缺、不可编**

## 最佳触发时间

- **北京时间 16:00 之后**:三大指数、成交额、板块涨跌幅、涨停家数一般已被财经网站汇总
- **15:00-16:00**:收盘后半小时,很多站点还在滚动更新,容易抓到"午盘数据"冒充收盘数据
- **次日 9:00 前**:昨日完整复盘数据最齐全
- **当日 15:00 前**:禁用本流程,此时仅能拿到盘中快照,不符合"收盘复盘"定义

## Phase 0:JSON API 优先抓取(首选,2026-04-27 新增)

> **2026-04-27 实战教训**:WebSearch + 文章页 WebFetch(原 Phase 1+2)在收盘后 0-2 小时内极不稳定 —— 搜索引擎索引滞后、JS 动态页面静态抓取拿不到值、AI 摘要把昨日数据冒充今日。**JSON API 不依赖 JS、不依赖搜索引擎索引,是收盘后立即可用的根本路径。**

**适用条件**:Phase 0 是 **默认首选**,任何时候都先走这一层。Phase 0 拿到 P0 字段后,**直接跳过 Phase 1**,只走 Phase 2 抓消息面。

**起手第一步(关键!避免最危险的"看似成功的错误"):**

对比"目标交易日"与"当前北京时间",决定指数/板块数据走哪个接口:

- **当天跑**(目标日 15:00 ~ 当天 24:00 之间):走 0.1 / 0.2 / 0.3(实时接口,数据就是目标日收盘)
- **跨日 / 周末 / 节假日跑**(已经跨过 0:00 到次日,或目标日是更早的日子):**指数/板块必须走 0.6 历史日线接口**(0.4 涨停池本身带 `date` 参数,继续用)
- 漏判这一步 → 拿到错数据但 skill 误以为正确(已知坑 #10),是最危险的失败模式 —— 接口不报错、数据结构正常、只有日期错位

### 主源:东方财富 push2 系列(纯 JSON,推荐)

#### 0.1 三大指数行情

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=1.000001,0.399001,0.399006,1.000688&fields=f2,f3,f4,f5,f6,f12,f14
```

返回 `data.diff` 数组 4 个元素,字段含义:
- `f2` 最新价 / `f3` 涨跌幅(%) / `f4` 涨跌额
- `f5` 成交量(手) / `f6` 成交额(元)
- `f12` 代码 / `f14` 名称

#### 0.2 行业板块涨跌幅榜

```
# 领涨(po=1 降序)
https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=50&po=1&np=1&fltt=2&fs=m:90+t:2+f:!50&fields=f3,f12,f14,f62,f128,f136

# 领跌:同 URL 改 po=0(升序)
```

字段:`f3` 板块涨跌幅 / `f62` 主力净流入 / `f128` 领涨股名称 / `f136` 领涨股涨跌幅。

#### 0.3 概念板块涨跌幅榜

URL 同 0.2,但 `fs=m:90+t:3+f:!50`(`t:3` 概念,`t:2` 行业)。两者都要抓 —— 行业板块代表大方向,概念板块代表当日热点。

#### 0.4 涨停 / 跌停股池

```
# 涨停池(date 用 8 位数字交易日,如 20260427)
https://push2ex.eastmoney.com/getTopicZTPool?ut=7eea3edcaed734bea9cbfc24409ed989&dpt=wz.ztzt&Pageindex=0&pagesize=200&sort=fbt:asc&date=YYYYMMDD

# 跌停池
https://push2ex.eastmoney.com/getTopicDTPool?ut=7eea3edcaed734bea9cbfc24409ed989&dpt=wz.ztzt&Pageindex=0&pagesize=200&sort=fund:asc&date=YYYYMMDD
```

返回含 `zttj`(连板数)、`hybk`(所属板块)、`fbt`(首次涨停时间)等字段。

#### 0.5 北向资金日度净流入

```
https://push2.eastmoney.com/api/qt/kamt.kline/get?fields1=f1,f3,f5&fields2=f51,f52&klt=1&lmt=5&ut=b2884a393a59ad64002292a3e90d46a5
```

返回近 5 日北向数据(`f51` 时间、`f52` 净额,单位:万元)。

> ⚠️ 2024-08 起官方不再公布盘中实时数据,只公布日终成交净买卖额,所以这个接口现在只能拿到日度数据,不是实时滚动。

#### 0.6 历史日线接口(跨日 / 周末复盘必用,2026-04-28 新增)

> **2026-04-28 实战教训**:0.1 / 0.2 / 0.3 是"当前最新"实时接口,跨日运行时(次日 9:30 后跑昨日复盘)拿到的是次日盘中数据,接口不报错、数据结构正常,**只有日期错位 —— 极易误用**。本接口是跨日 / 周末复盘的标准解决方案。

**接口 URL(单只查询)**:

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=<secid>&klt=101&fqt=0&beg=YYYYMMDD&end=YYYYMMDD&fields1=f1,f3&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
```

**适用范围**:

- ✅ **指数收盘数据**(上证、深成、创业板、科创 50)
- ✅ **个股 / 板块收盘数据**(已知 `secid` 时)
- ⚠️ **板块排名榜(领涨 / 领跌 TOP N)**:push2his 只能单只查询,无法直接出排名。跨日复盘的处理:
  - 优先选项:仍跑 0.2 / 0.3 实时接口取板块清单,**核对返回数据的时间戳是否为目标日**;若不是,再用 0.6 对每个板块代码补一次收盘价校正
  - 备选:走 Phase 1 文章页(同花顺、东财盘后综述,跨日后已索引完整,比当日跑稳)

**参数**:

- `secid`:单只代码
  - 上证综指:`1.000001`
  - 深证成指:`0.399001`
  - 创业板指:`0.399006`
  - 科创 50:`1.000688`
  - 板块:`90.BK<6 位板块代码>`(代码可从 0.2 / 0.3 实时接口的 `f12` 字段拿)
  - 个股:`1.<6 位代码>`(沪市)/ `0.<6 位代码>`(深市)
- `klt=101`:日 K 线(60 = 60 分钟,5 = 5 分钟)
- `fqt=0`:不复权
- `beg` / `end`:目标交易日 8 位数字(同一日两端相等,例 `20260427`)

**返回**(`data.klines` 数组,每行是逗号分隔字符串):

```
日期, 开盘, 收盘, 最高, 最低, 成交量(手), 成交额(元), 振幅(%), 涨跌幅(%), 涨跌额, 换手率(%)
```

**注意**:

- 四大指数收盘 = 4 次并行 WebFetch
- 接口稳定性高,周末、节假日、跨日都能查
- 起手判断决定走 0.1-0.5 实时接口 **或** 0.6 历史接口,**不要两个都跑** —— 数据不一致会让模型混乱

### 备源:腾讯财经(纯文本,极简)

```
https://qt.gtimg.cn/q=sh000001,sz399001,sz399006,sh000688
```

返回 4 行 `v_xxx="..."`,按 `~` 分割。索引 3 = 当前价、索引 32 = 涨跌幅。Phase 0 主源失败时的兜底。

### WebFetch 调 JSON API 的 prompt 模板

WebFetch 默认会让 LLM 总结网页内容。**对 JSON 接口,必须显式禁止总结、要求保留原始数值**:

```
该 URL 返回 JSON 格式数据。处理要求:
1. 不要总结、不要转译、不要润色
2. 提取 data.diff 数组中每项的字段:f3、f6、f12、f14、f62、f128
3. 按 f3 降序输出前 10 项,每行格式:
   "代码=f12 | 名称=f14 | 涨跌幅=f3% | 成交额=f6 | 净流入=f62 | 领涨股=f128"
4. 如果 JSON 解析失败或返回空数组,直接说"接口返回空"
```

### Phase 0 数据校验

- **时间戳匹配**:接口若有时间字段,确认是目标交易日
- **数据完整性**:行业板块榜应有 28+ 项,< 20 视为接口异常
- **数值范围**:个股涨跌幅 -10.5% ~ +10.5%,指数涨跌幅 |x| > 10% 视为异常
- **多接口交叉**:0.1 指数走势与 0.4 涨停跌停家数应自洽(普涨日涨停 ≥ 跌停)

### Phase 0 失败时的处理

- **单接口失败**(返回空 / 4xx / 5xx):等 3-5 秒重试 1 次,仍失败切备源
- **全部主源 + 备源失败**:走 Phase 1 WebSearch,但报告必须标明"Phase 0 全失败,数据来自二手综述,精度下降"
- **涨停池(0.4)偶尔返回空**:用 0.2 / 0.3 板块榜的领涨股(`f128`)间接补强 —— 领涨板块的领涨股很大概率就是涨停龙头

## Phase 1 / Phase 2:WebSearch + WebFetch 文章页(Phase 0 失败时的 fallback)

> 仅当 Phase 0 全部主源 + 备源都失败时,才回退到本路径。Phase 0 已能覆盖 P0 字段时,**只走 Phase 2 抓消息面**,不必跑 Phase 1。

### Phase 1:并行 WebSearch(找到具体文章 URL)

固定 URL(列表页/导航页)经常抓不到结构化数据,必须先搜到当天的具体报道页。并行发起以下 4-5 个搜索:

| 目的 | 推荐 query 模板 |
|------|----------------|
| 三大指数收盘 | `YYYY年M月D日 A股收盘 上证指数 深证成指 创业板指 科创50` |
| 板块涨跌榜 | `YYYY年M月D日 A股 板块涨跌幅排名 行业资金流` |
| 涨停梯队 | `YYYY年M月D日 A股 涨停家数 跌停 连板股 涨停梯队` |
| 资金流向 | `YYYY年M月D日 北向资金 净流入 主力资金` |
| 消息催化(按需) | `YYYY年M月D日 A股 [板块名] 催化/利好/消息` |

日期用 **中文格式**(`2026年4月24日`),比 `2026-04-24` 命中率高。

### Phase 2:并行 WebFetch(抓每个文章的结构化数据)

Phase 1 搜到的 URL 挑 3-5 个权威源并发抓取。每次抓取的 prompt **必须指定要提取的字段清单**,否则返回内容会很散。

**Prompt 模板**:

```
提取 YYYY 年 M 月 D 日 A 股【收盘/盘后】的以下字段,按清单列出,缺项标注"未获取":
1. 三大指数(上证/深证/创业板/科创50)收盘点位和涨跌幅
2. 全市场成交额(亿元)
3. 涨停家数、跌停家数(收盘值)
4. 连板梯队(3 板/2 板/首板)
5. 领涨板块 TOP 及涨跌幅
6. 领跌板块 TOP 及涨跌幅
7. 北向资金净流入、主力资金净额
8. 相关催化消息
```

## 已知坑(踩过的,别再踩)

1. **东财涨停复盘页 `cztfp.html` 是导航页**,直接 WebFetch 拿不到当日数据,必须先 WebSearch 找当日具体报道。
2. **新浪"今日 A 股市场重要快讯汇总"页**是 AI 自动生成,**往往没有 A 股指数数据**,主要覆盖外盘和上市公司公告——别指望它提供 P0 字段。
3. **同花顺复盘页**是动态滚动更新的,抓取时间戳若在收盘前 30 分钟,里面写的"今日"可能还是盘中数据。看到与其他源冲突时,以 16:00 之后的东财/证券时报文章为准。
4. **东财财富号午盘综述 ≠ 收盘综述**,标题里有"午盘""半日"的文章,其三大指数点位是 11:30 的收盘值,**不能当 15:00 收盘数据用**。抓完要反查标题。
5. **文章日期陷阱**:搜到的文章可能是"昨日复盘"(标题里写昨日日期),尤其是次日早上运行时。prompt 里必须带日期校验:"请确认是 YYYY 年 M 月 D 日的收盘数据而非盘中或前一日数据"。
6. **涨停数据的口径**:新浪/东财有时会把"涨停家数"包含 ST、一字板、连板,有时仅指主板——需要时以"含一字板总数"为准,不要混用口径。
7. **JS 动态行情页 WebFetch 必空(2026-04-27 验证)**:东财行情页(`http://quote.eastmoney.com/...`)、同花顺 `fupan/`、证券时报行情页都依赖 JS 渲染数据,WebFetch 静态抓取拿到的全是骨架占位符,**不要再尝试**。这类页面只能走 Phase 0 JSON API。
8. **搜索引擎 AI 摘要日期混淆(2026-04-27 验证)**:`A股收盘 2026年4月27日` 的搜索结果,Google/Bing AI 摘要会把上一交易日(4-24)的指数数据回填到摘要里,**还会带上"今日 4 月 27 日"的字样**,极具迷惑性。校验办法:任何 P0 字段从 Phase 1 拿到时,必须和 Phase 0 JSON 接口交叉对比;拿不到 Phase 0 数据时,把同一字段从至少 2 篇独立文章页(WebFetch 而非 AI 摘要)各取一遍,数值一致才采信。
9. **东财 push2ex 涨停池有限流(2026-04-27 反推)**:涨停池接口对高频访问敏感,偶尔返回空数组,这时不要反复重试,**用板块榜的领涨股(`f128`)间接推断涨停龙头**(详见 Phase 0 失败处理)。
10. **push2 实时接口的跨日陷阱(2026-04-28 实战)**:0.1 / 0.2 / 0.3 这些 push2 实时接口返回的是"当前最新"数据,**跨日运行时(次日 9:30 后跑昨日复盘)会拿到当前盘中数据,而非目标交易日的收盘数据**。接口本身不会报错,数据结构和正常调用一模一样 —— **模型极易把错数据当对数据用,且事后难以察觉**。这是 Phase 0 时代的最危险陷阱。规避方法:**起手第一步对比"目标日 vs 当前日"**,跨日时强制走 0.6 历史日线接口。push2ex 涨停池(0.4)因带 `date` 参数,不受此影响。

## 数据冲突与校验

多源对同一字段给出不同数据时,按以下优先级采信:

1. **时间晚的优先**:16:00 后文章 > 14:00 文章 > 午盘文章
2. **权威源优先**:东财官方盘后综述 > 财富号自媒体 > 第三方转载
3. **精度高的优先**:带小数点(如 -0.33%)> 模糊表述(如"小幅下跌")

**强制校验项**(抓完 P0 数据后,在产出前逐条检查):

- [ ] 三大指数的涨跌幅和点位算术自洽(涨跌点位 ≈ 昨收 × 涨跌幅)
- [ ] 成交额与"放量/缩量"描述不矛盾(成交额环比变化要与描述一致)
- [ ] 涨停家数 ≥ 连板梯队总数(3 板数 + 2 板数 ≤ 涨停家数)
- [ ] 领涨板块代表个股,要出现在涨停梯队或首板列表里(如"锂电领涨"则锂电相关个股应在首板名单中)
- [ ] 消息面日期与复盘日期一致(不要把前一日政策当今日催化)

任何一项失败,**标注"数据存疑,以 XXX 源为准"**,不强行消弭矛盾。

## 容错降级规则

按数据完整度分三档输出:

### 档位 A:P0 字段齐全(三大指数 + 成交额 + 涨停梯队)

正常按 SKILL.md 10 段输出,数据缺失项逐条标注"未获取",**不降级**。

### 档位 B:P0 缺 1-2 项(例如缺成交额或缺连板梯队)

- 报告开头顶部加一行:"本次复盘因缺失 XX 数据,完整性受限,请结合其他来源参考"
- 缺失字段涉及的段落(如量能/情绪面),**只做定性分析,不做定量判断**
- 预测部分的"依据"必须避开缺失字段(例如缺成交额时,量能类依据不可作为预测支撑)

### 档位 C:P0 缺 3 项及以上

- **不输出完整复盘报告**,改为向用户说明:"公开源今日数据覆盖不足,无法完成合格复盘。可能原因:数据源限流 / 网络阻断 / 当日为非交易日。建议稍后重试或手动贴入数据。"
- 附上已抓到的片段信息作为参考,但明确标注为"片段信息,不构成复盘"
- 避免硬写一份"看起来像但内容靠猜"的报告——这违反 skill 核心约束

---

## 禁止行为(违反即整份报告作废)

1. **禁止凭记忆补全数据**。即使你"印象中"昨天沪指是 4093 点,只要今日数据源没给出,就标"未获取"。
2. **禁止把昨日数据当今日数据**。搜索结果里经常混入前一日数据,确认日期是强制动作。
3. **禁止用"约""大约""估计"来美化缺失**。要么有数据,要么没数据。
4. **禁止把盘中数据写成收盘数据**。午盘 / 收盘前数据要明确前缀标注(如"上午 52 只涨停")。
5. **禁止把定性描述当定量数据**。"煤炭走强"≠"煤炭 +2.49%",前者不能出现在涨幅数值位。

## 抓取效率建议

一次完整抓取预算:**Phase 0 ≤ 6 次 WebFetch + Phase 2 ≤ 3 次 WebSearch + 2 次 WebFetch**(并行执行,总耗时约 30-60 秒)。超过这个量级说明数据源失效,应该换策略而非盲目加次数。

**新版顺序(Phase 0 优先)**:
1. **Phase 0**:并行发 5-6 次 WebFetch 调 JSON API(0.1 指数 + 0.2 行业 + 0.3 概念 + 0.4 涨停 + 0.5 北向)
2. 校验 Phase 0 数据(数值合理性、时间戳、跨接口自洽)
3. **Phase 0 拿到 P0 字段** → 跳过 Phase 1,**直接进入 Phase 2 抓消息面**(并行 2-3 次 WebSearch)
4. **Phase 0 P0 字段缺失** → 才回退到 Phase 1 WebSearch + Phase 2 WebFetch 文章页
5. 终止抓取,进入写作
