# 港股数据抓取清单与容错逻辑

> 本文件是 `SKILL.md` 的配套执行手册。本 skill 在 **Claude Code / Cursor CLI** 中运行,所有行情、资金、消息数据都需要通过 `WebFetch` / `WebSearch` 自行抓取。本文是这一抓取流程的标准操作手册 —— 避免每次都从零摸索,也避免误用数据。

---

## 何时使用本流程

**本流程是默认流程**:用户每次触发港股复盘 skill,都按本文执行。

适用条件:
- 在 Claude Code / Cursor CLI 中调用 skill(WebFetch / WebSearch 可用)
- 复盘对象是当日已收盘的港股市场(或最近一个港股交易日)
- 数据抓取覆盖率无需 100%,**宁可缺、不可编**

## 最佳触发时间(港股口径)

港股交易时段(北京时间):
- 早盘:9:30 - 12:00
- 午盘:13:00 - 16:00
- 收市后竞价时段:16:00 - 16:10(VCM/CAS,价格仍在变化)

最佳触发窗口:
- **北京时间 16:30 之后**:CAS 已结束,三大指数和大市成交已稳定;南向资金通常 17:00-18:00 才完整披露
- **17:00-18:00 之后**:南向资金日终数据齐全,**最佳的复盘窗口**
- **次日 9:00 前(港股开盘前)**:数据完整度最高,适合补跑或周末跑前一交易日
- **当日 16:00 前**:禁用本流程,此时仅能拿到盘中快照,不符合"收盘复盘"定义

## 起手判断(关键!避免最危险的"看似成功的错误")

抓数据前,**必须先回答以下三个问题**,根据答案决定接口选择:

### Q1:目标交易日是哪一天?(港股交易日历)

港股交易日历 **与 A 股不完全同步**:
- 港股自有节假日:**圣诞节(12 月 25-26 日)、复活节、香港佛诞、香港特别行政区成立纪念日(7 月 1 日)** 等休市
- A 股自有节假日:春节假期通常比港股长(港股农历新年只休 1-3 日,A 股休 7 日);国庆节港股仅休 1 日
- 综合后:**A 股开市但港股休市** / **港股开市但 A 股休市** 的情况都存在
- **南向资金通道的开闭规则**:任一边休市 → 南向通道关闭 → 当日无南向数据

**判断方法**:抓数据前,WebSearch `YYYY 年 M 月 D 日 港股 是否交易`(若不确定),或检查 `100.HSI` 历史日线接口能否取到目标日数据(返空说明休市)。

### Q2:当前北京时间相对目标交易日是什么状态?

| 当前时间相对目标日 | 接口策略 |
|---|---|
| 目标日 16:00 - 23:59 | 走 **实时接口**(Phase 0 的 1.x / 2.x / 3.x),数据就是目标日收盘 |
| 跨日(次日 0:00 之后)/ 周末 / 节假日跑 | **必须走 push2his 历史日线接口**(Phase 0 的 1.b / 2.b 等) |
| 目标日 16:00 前 | **禁止跑**,数据不是收盘值 |

**漏判 Q2 → 拿到错数据但 skill 误以为正确(已知坑 #1),是最危险的失败模式 —— 接口不报错、数据结构正常、只有日期错位**。

### Q3:南向资金接口能拿到目标日数据吗?

datacenter `RPT_MUTUAL_DEAL_HISTORY` 是日终数据,通常 **目标日 17:00 后** 才有当日数据。
- 目标日 17:00 前抓 → 拿到的是上一交易日数据,**必须延后或承认缺数据**
- 跨日跑(次日早上之后) → 一定有,正常使用
- 通道关闭日 → 接口返空,这是正常情况,不是故障

## Phase 0:JSON API 优先抓取(默认首选)

> 港股域的 push2 接口不像 A 股那么完整,**有几个硬限制**(详见"已知坑"#3-#5),但能拿到的字段稳定性很高。Phase 0 拿到 P0 字段后,**直接进入 Phase 2 抓消息面**。

### 主源:东方财富 push2 / datacenter(基于 2026-05-08 实测探测)

#### 1.a 三大港指实时(目标日 16:00 ~ 23:59 用)

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=100.HSI,100.HSTECH,100.HSCEI&fields=f2,f3,f4,f5,f6,f12,f14
```

字段:
- `f2` 收盘价 / `f3` 涨跌幅(%) / `f4` 涨跌点
- `f5` 成交量(股) / `f6` 成交额(港币)
- `f12` 代码 / `f14` 名称

**实测 2026-05-08 返回**:HSI 26393.71 / -0.87% / -232.57;HSTECH 5102.79 / -0.36%;HSCEI 8889.07 / -0.34%。

> ⚠️ secid 用 `100.` 前缀最稳。`124.HSI` 也通,但 `124.HSTECH` 在历史接口会返 `data:null`,**统一用 `100.` 前缀避免分裂**。

#### 1.b 三大港指历史日线(跨日 / 周末 / 节假日复盘必用)

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=100.HSI&klt=101&fqt=0&beg=YYYYMMDD&end=YYYYMMDD&fields1=f1,f3&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
```

返回 `data.klines` 数组(每行逗号分隔):

```
日期, 开盘, 收盘, 最高, 最低, 成交量, 成交额, 振幅%, 涨跌幅%, 涨跌额, 换手率%
```

四只指数 = 4 次并行 WebFetch:
- 恒生指数:`secid=100.HSI`
- 恒生科技:`secid=100.HSTECH`
- 国企指数:`secid=100.HSCEI`
- AH 溢价指数:`secid=100.HSAHP`(成交量/额恒为 0,正常)

**实测 2026-05-08**:`100.HSI` 返 `"2026-05-08,26359.79,26393.71,26470.49,26274.80,14378780416,279754473472.00,0.73,-0.87,-232.57,0.00"`。

#### 2.a 港股个股实时(目标日 16:00 ~ 23:59 用)

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=116.00700,116.09988,116.03690,...&fields=f2,f3,f4,f5,f6,f12,f14
```

**港股个股 secid 必须用 `116.<5 位代码>`**(5 位前导 0 必填)。例:
- 腾讯 → `116.00700`(不能写 `116.700`)
- 阿里 → `116.09988`
- 美团 → `116.03690`
- 比亚迪 → `116.01211`
- 工商银行 → `116.01398`
- 中国平安 → `116.02318`
- 汇丰控股 → `116.00005`
- 友邦保险 → `116.01299`
- 长和 → `116.00001`

**实测 2026-05-08**:`116.00700` 返腾讯 471.4 / -1.26% / 成交 25,207,039 股。

#### 2.b 港股个股历史日线

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=116.00700&klt=101&fqt=0&beg=YYYYMMDD&end=YYYYMMDD&fields1=f1,f3&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
```

字段同 1.b。一次只能查一只股,需要并行多发。

#### 3.a 恒生综合行业指数(港股域唯一可用的"行业视角")

> ⚠️ 港股域 **没有 A 股 `m:90+t:2` 那样的行业板块涨跌幅榜接口**。东财所有 RPT_HKSTOCK_INDUSTRY/RPT_HK_BK_RANK 接口返"报表配置不存在"。能拿到涨跌幅数据的恒生综合行业指数 **实测仅 3 个**(其余 7-9 个硬编码 secid 全部返空)。

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=124.HSCIIT,124.HSCIPC,124.HSCITC&fields=f2,f3,f4,f5,f6,f12,f14
```

**实测 2026-05-08**:
- `124.HSCIIT` 资讯科技业:14845.14 / -0.99%
- `124.HSCIPC` 地产建筑业:1950.9 / +0.21%
- `124.HSCITC` 电讯业:1773.83 / +0.6%

**返空的硬编码 secid(已验证不可用)**:`124.HSCIE`(能源)、`124.HSCIF`(金融)、`124.HSCICG`(必需消费)、`124.HSCIIG`(可选消费)、`124.HSCIM`(原材料)、`124.HSCIU`(公用事业)、`124.HSCIH`(医疗保健)。**写入清单时只列上面 3 个,其他不要再尝试**。

#### 3.b 恒生综合行业历史日线(跨日时用)

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=124.HSCIIT&klt=101&fqt=0&beg=YYYYMMDD&end=YYYYMMDD&fields1=f1,f3&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
```

仅对 HSCIIT / HSCIPC / HSCITC 三个 secid 有效。

#### 4. AH 溢价指数(HSAHP)

实时:同 1.a,把 `secids` 加上 `100.HSAHP`。

历史:同 1.b,`secid=100.HSAHP&klt=101&...`

**实测 2026-05-08**:HSAHP 收盘 119.06 / +0.44%(开 118.70 / 收 119.06 / 高 119.41 / 低 118.70)。

> ⚠️ HSAHP 历史日线 **成交量与成交额恒为 0** 是正常(指数本身不成交),不是接口故障。

#### 5. 南向资金(港股复盘的核心数据)

**主接口**:东财 datacenter

```
https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_MUTUAL_DEAL_HISTORY&columns=ALL&filter=(MUTUAL_TYPE=%22006%22)&sortColumns=TRADE_DATE&sortTypes=-1&pageSize=10
```

**MUTUAL_TYPE 编码(只有这三个对港股复盘有用)**:
- `002`:沪港通南向(从内地买香港股票,沪市发起)
- `004`:深港通南向(从内地买香港股票,深市发起)
- `006`:**南向合计 = 002 + 004**(默认抓这个)

> ⚠️ `001/003/005` 是北向(内地股票通道,A 股域),抓港股复盘 **不要用** —— 实测这三个的 NET_DEAL_AMT/BUY_AMT/SELL_AMT 字段全为 null,LEAD_STOCKS 是 A 股名称。

**关键字段**:
- `TRADE_DATE` 交易日
- `NET_DEAL_AMT` 净买入(亿港元,正负数)
- `BUY_AMT` 总买入金额
- `SELL_AMT` 总卖出金额
- `LEAD_STOCKS_NAME` 当日龙头股名称
- `HOLD_MARKET_CAP` 港股通持股市值(累计)
- `INDEX_CHANGE_RATE` 当日恒指涨跌幅(用于交叉校验)

**实测 2026-05-08**:
- 南向合计(006):净买入 +131.68 亿港元;龙头股健康 160 +44.26%;持股市值 12.99 万亿
- 沪南向(002):净买入 +101.26 亿
- 深南向(004):净买入 +30.43 亿
- 自洽:101.26 + 30.43 = 131.69 ≈ 131.68(小数精度差) ✓

**南向资金 TOP 净买入/净卖出个股榜**(港股通成交活跃股):

```
https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_MUTUAL_STOCK_NORTHSTA&columns=ALL&filter=(MUTUAL_TYPE="006")(TRADE_DATE='YYYY-MM-DD')&sortColumns=NET_DEAL_AMT&sortTypes=-1&pageSize=20
```

> ⚠️ 此接口名虽叫 `NORTHSTA` 但 MUTUAL_TYPE=006 是南向数据。如果接口返回异常,WebSearch `东财 港股通成交活跃股 实时` 找当前可用的 datacenter 接口名。

> ⚠️ **南向资金日终接口的更新延迟**:目标日 17:00 之前查 `TRADE_DATE` 排在最前的可能是上一交易日,要看返回数据的 `TRADE_DATE` 字段是否等于目标日。

#### 6. 中概 ADR(美股标的,作为隔夜锚点)

港股个股的美股映射用 `105.<美股代码>`(纳斯达克)或 `106.<美股代码>`(纽交所):

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=105.BABA,105.JD,105.PDD,105.NTES,105.BILI&fields=f2,f3,f4,f5,f6,f12,f14
```

**注意**:中概 ADR 是美股交易时段的数据,北京时间 21:30-次日 4:00 才在交易。如果目标日的中概 ADR 数据要用 **前夜**(即北京时间昨晚)的收盘,需要用 push2his 拿前一日的数据。中概互联网 ETF KWEB:`105.KWEB`。

#### 7. 美股标杆(前夜行情,作为外盘传导依据)

```
https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=100.DJIA,100.NDX,100.SOX,100.SPX&fields=f2,f3,f4,f5,f6,f12,f14
```

- 道指 `100.DJIA`
- 纳指 `100.NDX`
- 费半 `100.SOX`
- 标普 `100.SPX`

或用历史日线接口取前一交易日收盘,避免实时接口在美股盘中拿到非收盘值。

### 备源:腾讯财经(纯文本,极简兜底)

```
https://qt.gtimg.cn/q=hk00700,hkHSI,hkHSCEI,hkHSTECH
```

**港股代码格式**:`hk<5 位代码>`(如 `hk00700`)或 `hk<指数代码>`(如 `hkHSI`)。返回按 `~` 分割,索引 3 = 当前价、索引 32 = 涨跌幅。

主源失败时的兜底,不替代 datacenter 的南向接口(腾讯没有南向数据)。

### WebFetch 调 JSON API 的 prompt 模板

WebFetch 默认会让 LLM 总结网页内容。**对 JSON 接口,必须显式禁止总结、要求保留原始数值**:

```
该 URL 返回 JSON 格式数据。处理要求:
1. 不要总结、不要转译、不要润色
2. 提取 data.diff 数组中每项的字段:f2, f3, f4, f5, f6, f12, f14
3. 按 f3 降序输出,每行格式:
   "代码=f12 | 名称=f14 | 收盘=f2 | 涨跌幅=f3% | 涨跌点=f4 | 成交量=f5 | 成交额=f6"
4. 如果 JSON 解析失败或返回空数组,直接说"接口返回空"
```

### Phase 0 数据校验

- **时间戳匹配**:接口若有时间字段,确认是目标交易日
- **南向加总自洽**:沪南向(002) + 深南向(004) ≈ 南向合计(006),误差 < 0.1 亿
- **数值范围**:港指涨跌幅 |x| > 5% 视为异常需复核;南向单日净额 |x| > 300 亿罕见
- **多接口交叉**:南向接口的 `INDEX_CHANGE_RATE` 与 1.a 取到的恒指 `f3` 应一致

### Phase 0 失败时的处理

- **单接口失败**(返回空 / 4xx / 5xx):等 3-5 秒重试 1 次,仍失败切备源
- **datacenter 南向接口超时**:用 WebSearch + WebFetch 走东财港股通频道文章页(Phase 1)
- **腾讯备源也失败**:走 Phase 1 WebSearch 路径,但报告必须标明"Phase 0 全失败,数据来自二手综述,精度下降"

## Phase 1 / Phase 2:WebSearch + WebFetch 文章页(Phase 0 失败时的 fallback)

> 仅当 Phase 0 全部主源 + 备源都失败时,才回退到本路径。Phase 0 已能覆盖 P0 字段时,**只走 Phase 2 抓消息面**,不必跑 Phase 1。

### Phase 1:并行 WebSearch(找到具体文章 URL)

| 目的 | 推荐 query 模板 |
|------|----------------|
| 三大指数收盘 | `YYYY年M月D日 港股收盘 恒生指数 恒生科技 国企指数` |
| 行业板块榜(港股域无主源时必用) | `YYYY年M月D日 港股 板块涨跌幅 行业资金流` |
| 南向资金 | `YYYY年M月D日 南向资金 净流入 港股通` |
| AH 溢价 | `YYYY年M月D日 AH 溢价指数 港股 折价` |
| 中概 ADR | `YYYY年M月D日 中概股 ADR 阿里 京东 拼多多` |
| 消息催化 | `YYYY年M月D日 港股 [板块名/个股] 利好/利空` |

日期用 **中文格式**(`2026年5月8日`),命中率高于 `2026-05-08`。

### Phase 2:并行 WebFetch(抓每个文章的结构化数据)

Phase 1 搜到的 URL 挑 3-5 个权威源(同花顺港股频道、东财港股频道、新浪港股、富途、雪球)并发抓取。每次抓取的 prompt **必须指定要提取的字段清单**。

**Prompt 模板**:

```
提取 YYYY 年 M 月 D 日 港股【收盘/盘后】的以下字段,按清单列出,缺项标注"未获取":
1. 三大指数(恒生/恒生科技/国企)收盘点位和涨跌幅
2. 大市成交额(亿港元)
3. 主板涨跌家数
4. 南向资金净流入(沪南向 + 深南向 + 合计)
5. 港股通成交活跃股 TOP 10(净买入/净卖出)
6. AH 溢价指数收盘值与变动
7. 行业板块涨跌(若文章有)
8. 关键消息(政策/个股事件/外盘)
```

## 字段优先级与推荐数据源

> 每个字段下,**第一行是 Phase 0(JSON API)首选源,第二行是 Phase 1/2(WebSearch+文章页)的备选**。

### P1 尽量抓(缺失在对应段标注)

| 字段 | 首选 | 备选 |
|------|------|--------|

### P2 加分项(够时间就抓,不够就跳)

- 5 日 / 20 日累计南向净额趋势(用 datacenter pageSize=20 取多日)
- AH 双重上市股价差对比表(需并行抓 116. 港股 + 1.沪 / 0.深 A 股)
- HIBOR 港币同业拆息(需 WebSearch,主源无 JSON 接口)
- 港币兑美元汇率走势(需 WebSearch / 备源)

## 已知坑(踩过的,别再踩)

1. **push2 实时接口的跨日陷阱(继承自 A 股 skill)**:1.a / 2.a / 3.a 这些 push2 实时接口返回的是"当前最新"数据,**跨日运行时(次日 9:30 后跑昨日复盘)会拿到当前盘中数据,而非目标交易日的收盘数据**。接口本身不会报错,数据结构和正常调用一模一样 —— **模型极易把错数据当对数据用,且事后难以察觉**。规避方法:**起手第一步对比"目标日 vs 当前日"**,跨日时强制走 push2his 历史日线接口(1.b / 2.b / 3.b)。

2. **港股交易日历不同步**:港股自有节假日(圣诞、复活节、佛诞、香港回归纪念日等)A 股不休,反之 A 股春节假期港股仅休 1-3 日。**抓数据前必须先确认目标日是港股交易日**。判断:WebSearch 或调 1.b 历史接口看是否返数。任一边休市 → 南向通道关闭。

3. **港股域无行业板块涨跌幅榜**(2026-05-09 探测确认):东财所有 datacenter 候选(`RPT_HKSTOCK_INDUSTRY` / `RPT_HK_BK_RANK` / `RPT_HKSTOCK_BK`)全返"9501 报表配置不存在"。push2 域 `m:124+t:X` 全部返 `data:null`(rc:102)。`m:116+t:X` 是港股个股全集而非行业。`m:155+t:1` 是全球指数大杂烩(含瑞士/美国/欧债)。**A 股 `m:90+t:2` 那种"行业板块榜单"在港股域就是没有**。代偿:用 3.a 硬编码 3 个能用的恒生综合行业指数(HSCIIT/HSCIPC/HSCITC)+ 5 的港股通成交活跃股 TOP 10 反推板块情绪。

4. **恒生综合行业 secid 大半返空**:实测仅 `124.HSCIIT`(资讯科技)、`124.HSCIPC`(地产建筑)、`124.HSCITC`(电讯)三个返数据。HSCIE(能源)/HSCIF(金融)/HSCICG(必需消费)/HSCIIG(可选消费)/HSCIM(原材料)/HSCIU(公用)/HSCIH(医疗)硬编码 secid 全部返空。**不要再反复尝试这 7 个**,直接走 Phase 1 文章页补这 7 个行业的视角。

5. **港股 secid 前缀不统一**:三大港指用 `100.`(`100.HSI`/`100.HSTECH`/`100.HSCEI`)、个股用 `116.`(`116.<5 位>`)、恒生综合行业用 `124.`(`124.HSCIxx`)、AH 溢价用 `100.`(`100.HSAHP`)、中概 ADR 用 `105.`(纳市)/`106.`(纽交所)。**不能混用**(如 `116.HSI` 会失败,`124.00700` 也会失败)。

6. **港指 secid 双前缀但只有一个稳**:`100.HSI` 和 `124.HSI` 实时接口都返同样数据,但**历史日线接口 124. 前缀对 HSTECH 直接 `data:null`**。**统一用 `100.` 前缀**最安全,这是项目标准。

7. **港股个股代码必须 5 位前导 0**:`116.00700` 通,`116.0700`、`116.700` 都会失败。腾讯 = 700 → `116.00700`,长和 = 1 → `116.00001`。

8. **kamt.kline 接口在港股域返 0**:A 股北向用 `kamt.kline`(`f51` 时间 `f52` 净额)很稳,**港股南向 NOT 工作** —— `s2n` 字段全为 `"0.00"`,**不要用此接口取南向**。必须改用 datacenter `RPT_MUTUAL_DEAL_HISTORY`。

9. **MUTUAL_TYPE 编码陷阱**:001=沪股通北向、003=深股通北向、005=北向合计(这三个 NET_DEAL_AMT/BUY_AMT/SELL_AMT 都是 null,且 LEAD_STOCKS 是 A 股名称);**只有 002=沪港通南向、004=深港通南向、006=南向合计这三个对港股复盘有用**。

10. **HSAHP 历史日线成交量/额恒为 0** 是正常(指数本身无成交),不是接口故障。校验时不要把"成交量=0"当作数据缺失。

11. **南向资金延迟披露**:datacenter 接口在目标日 **17:00 前** 返回的"最新数据"通常是上一交易日,而不是目标日。**校验**:返回数据的 `TRADE_DATE` 字段是否等于目标日;若不等,提示用户延后或承认缺数据。

12. **南向通道关闭日**:港股或 A 股任一休市,南向通道关闭,当日 datacenter 返空 / `TRADE_DATE` 跳过该日。**这是正常情况,不是接口故障**。

13. **中概 ADR 时区**:中概 ADR 在美股盘中(北京时间 21:30 - 次日 4:00),数据时点和港股完全错开。复盘时要明确"前夜美股收盘"指的是 **目标日早上 4:00 美股收盘的那一夜**,不是更早的。用 push2his 拿对应美股交易日的数据更稳。

14. **AI 摘要日期混淆(继承自 A 股)**:WebSearch 拿到的 AI 摘要会把上一交易日数据回填到当日描述,极具迷惑性。校验办法:任何 P0 字段从 Phase 1 拿到时,必须和 Phase 0 JSON 接口交叉对比;拿不到 Phase 0 数据时,把同一字段从至少 2 篇独立文章页(WebFetch 而非 AI 摘要)各取一遍,数值一致才采信。

15. **JS 动态行情页 WebFetch 必空(继承自 A 股)**:东财港股行情页、富途行情页、同花顺动态页都依赖 JS 渲染数据,WebFetch 静态抓取拿到的全是骨架占位符。这类页面只能走 Phase 0 JSON API 或 Phase 1 文章页(纯文本)。

## 数据冲突与校验

多源对同一字段给出不同数据时,按以下优先级采信:

1. **时间晚的优先**:17:00 后文章 > 16:30 文章 > 16:00 前文章
2. **权威源优先**:东财 push2 / datacenter > 同花顺/富途 > 第三方转载
3. **精度高的优先**:带小数点的数值 > 模糊表述

**强制校验项**(抓完 P0 数据后,在产出前逐条检查):

- [ ] 三大港指的涨跌幅和点位算术自洽(涨跌点位 ≈ 昨收 × 涨跌幅)
- [ ] 大市成交额与"放量/缩量"描述不矛盾
- [ ] 沪南向(002) + 深南向(004) ≈ 南向合计(006),误差 < 0.1 亿
- [ ] datacenter 南向接口的 `INDEX_CHANGE_RATE` 与 push2 取到的恒指 `f3` 一致
- [ ] 港股通成交活跃股的方向(净买入/净卖出 TOP)与南向合计净额方向自洽(普遍净买日,净买 TOP 数量应远多于净卖)
- [ ] 消息面日期与复盘日期一致(不要把前一日政策当今日催化)
- [ ] 中概 ADR 数据是 **目标港股交易日的前夜美股收盘**(注意时区)

任何一项失败,**标注"数据存疑,以 XXX 源为准"**,不强行消弭矛盾。

## 容错降级规则

按数据完整度分三档输出:

### 档位 A:P0 字段齐全(三大港指 + 大市成交 + 南向合计 + AH 溢价)

正常按 SKILL.md 10 段输出,数据缺失项逐条标注"未获取",**不降级**。第 4-5 节用"恒生 3 大行业 + 南向 TOP"双视角。

### 档位 B:P0 缺 1-2 项(例如缺南向资金或缺 AH 溢价)

- 报告开头顶部加一行:"本次复盘因缺失 XX 数据,完整性受限,请结合其他来源参考"
- 缺失字段涉及的段落(如缺南向 → 第 7 节、第 4-5 节的 4.2/5.2 子段),**只做定性分析,不做定量判断**
- 预测部分的"依据"必须避开缺失字段(例如缺南向时,资金类依据不可作为预测支撑)
- **特例**:若缺南向是因为目标日是南向通道关闭日(A 股或港股一边休市),不算降级,正常输出但第 7 节需说明"今日通道关闭无南向数据,行情主由外资和本地资金主导"

### 档位 C:P0 缺 3 项及以上

- **不输出完整复盘报告**,改为向用户说明:"公开源今日数据覆盖不足,无法完成合格复盘。可能原因:数据源限流 / 网络阻断 / 当日为非交易日 / 数据披露延迟。建议稍后(尤其 17:00 后)重试或手动贴入数据。"
- 附上已抓到的片段信息作为参考,但明确标注为"片段信息,不构成复盘"
- 避免硬写一份"看起来像但内容靠猜"的报告 —— 这违反 skill 核心约束

## 禁止行为(违反即整份报告作废)

1. **禁止凭记忆补全数据**。即使你"印象中"上周恒指是 26500 点,只要今日数据源没给出,就标"未获取"。
2. **禁止把 A 股交易日 = 港股交易日**。港股有独立日历,先验证。
3. **禁止把上一交易日数据当目标日数据**。push2 实时接口跨日 / 南向接口延迟披露都会触发此陷阱。
4. **禁止用"约""大约""估计"来美化缺失**。要么有数据,要么没数据。
5. **禁止把盘中数据写成收盘数据**。CAS(16:00-16:10)价格仍在变化,16:00 前的快照不是收盘价。
6. **禁止硬凑 7 个行业**。港股能拿到涨跌幅的恒生综合行业实测就 3 个,不要为了对齐 A 股骨架而编造剩下的。
7. **禁止把中概 ADR 前夜数据当作今日港股表现**。两者是不同时段的不同标的。

## 抓取效率建议

一次完整抓取预算:**Phase 0 ≤ 8 次 WebFetch + Phase 2 ≤ 3 次 WebSearch + 2 次 WebFetch**(并行执行,总耗时约 40-80 秒)。

**推荐顺序(Phase 0 优先)**:

1. **起手判断**(1 分钟内):确认目标交易日 + 时段 + 港股交易日历 + 南向通道是否开放
2. **Phase 0 第一波**(并行 5 次 WebFetch):
   - 1.a/1.b 三大港指(实时或历史,二选一)
   - 3.a/3.b 恒生 3 大行业
   - 4 AH 溢价指数
   - 5 南向资金合计 + 沪深拆分(datacenter)
   - 7 前夜美股 + 6 中概 ADR
3. **Phase 0 第二波**(并行 2-3 次 WebFetch):
   - 5 港股通成交活跃股 TOP 10
   - 2.a/2.b 关键港股个股(腾讯/美团/阿里/比亚迪等,作为权重股印证)
4. **校验 Phase 0 数据**(数值合理性、时间戳、跨接口自洽)
5. **Phase 0 P0 字段齐全** → 跳过 Phase 1,**直接进入 Phase 2 抓消息面**(并行 2-3 次 WebSearch)
6. **Phase 0 P0 字段缺失** → 才回退到 Phase 1 WebSearch + Phase 2 WebFetch 文章页
7. 终止抓取,进入写作

超过这个量级说明数据源失效,应该换策略而非盲目加次数。
